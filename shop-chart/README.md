# Helm chart shop

The chart deploys the API and worker, and by default creates a PostgreSQL
CloudNativePG `Cluster`. The application uses a PostgreSQL Secret generated by
CloudNativePG (`<release>-postgres-app`, key `uri`). The database bootstrap SQL
creates the `orders` table and index.

The API and worker images default to `docker.io/library/shop-api:v2` and
`docker.io/library/shop-worker:v1`. Build and load them into kind from the
repository root:

```bash
docker build -t docker.io/library/shop-api:v2 \
  -f shop-services/api/Dockerfile ./shop-services
docker build -t docker.io/library/shop-worker:v1 \
  -f shop-services/worker/Dockerfile ./shop-services
kind load docker-image docker.io/library/shop-api:v2 \
  docker.io/library/shop-worker:v1 --name lab5
```

Base values keep API as `ClusterIP` and leave NetworkPolicy disabled. The
[`values-lab5.yaml`](./values-lab5.yaml) overlay configures API as a `NodePort`
and enables namespace default-deny plus the lab's explicit allow rules. Use it
only with a CNI that enforces Kubernetes NetworkPolicy, such as Cilium.

The chart also renders a `ServiceMonitor` for API/worker and a `PrometheusRule`.
The Prometheus Operator CRDs must exist before installing the release. The
dashboard JSON is imported into Grafana separately.

Lab5 cluster bootstrap, command sequence, fault injection and report evidence
are documented in the [lab-5 report](../lab-5/report.md).

Validate and render from the repository root:

```bash
helm lint ./shop-chart
helm template shop ./shop-chart --namespace shop \
  -f shop-chart/values-lab5.yaml
```
